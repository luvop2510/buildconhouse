# Team access, performance and concealed-part review — 2026-10-11

Source fixes are implemented locally. The authorized production account reset is complete and normal service has been restored. Publishing the source changes remains blocked by the required pre-existing npm security gate.

## Implemented changes

- Team uses Owner or Delegated staff. Enabling a floor exposes its pages; multiple pages and their individual actions save together. Repeated page enables retain selected actions. Editing fetches current grants rather than overwriting them with stale list data. Invalid grants fail closed, including disabled floors, unsupported pages/actions and missing View actions.
- Replaced the obsolete role-matrix implementation with a Team redirect and removed redundant Settings access links. Replaced the obsolete singular brand analytics page with a redirect to the current plural route, retaining reporting parameters. Excluded retained frontend checkout, backend, generated output and evidence directories from Metro scanning. The retained checkout is not part of the deployed app and was not deleted.
- Quotation-only staff can read the bounded catalog/customer dependencies necessary for building a quotation without gaining the separate Catalog/Customers pages or generic catalog mutations. Builder entry and internal recovery/new/edit commands enforce Create/Edit separately. Create-only staff retain a local draft and submit once explicitly; they do not trigger an unauthorized autosave PATCH.
- Concealed parts selected in the builder persist to the exact product before addition. Failed saves add nothing. Fresh family loading retains the saved association; selected variants/recent/frequent products refresh after saves. Hydration respects explicit product identity instead of choosing an unrelated same-SKU product. Retired, foreign-floor or ambiguous parts are not substituted.
- Concealed lines retain parent IDs and quantity ratios when reopening quotations. Quantity, room, removal, duplication and swaps keep the pair consistent. Existing quotation price snapshots are preserved when catalog associations/prices change.
- Dashboard sections render as their requests finish, rather than waiting for the slowest of six requests. It skips requests and links for pages the account cannot access. Explicit refresh bypasses the completed response cache on web and native. The backend dashboard cache includes user identity because assigned follow-ups differ between users.
- Desktop quotation grids now retain four columns until the pane reaches 720px; the prior five-column layout at 520px squeezed cards enough for the favorite button to cover the image center.
- Catalog family pagination now performs detailed variant/media/configuration hydration only for the requested page. Explicit concealed-part identity lookup also avoids repeated catalog scans.
- Dynamic notebook floor segments now resolve before page authorization, navigation highlighting and floor compatibility checks; this fixes delegated Walk-ins redirect loops and owner floor-switch spinners. Nested overlay isolation now keeps the topmost picker interactive and restores the underlying dialog when it closes.
- Kitchen/Furniture notebook wrappers wait for floor authorization before fetching; floor changes remount their state. Async callbacks avoid stale screen updates. Create/Edit controls follow action grants. Furniture WhatsApp configuration loads independently of the ledger and is not repeatedly fetched on pagination; Export grants govern send/status. Configuration failures preserve PDF access and offer retry. Monetary fields reject negative/nonfinite/invalid values consistently.

## Performance evidence

Read-only Railway metrics for the preceding 24 hours showed catalog-family bucket p95 as high as **5,551 ms**. Backend CPU averaged approximately **0.0042 cores**, peaking near **0.1817**, so the observed data does not establish CPU capacity exhaustion. The backend is in SFO; database-region colocation and Indian-client latency still need measurement before choosing an infrastructure move.

A synthetic parity benchmark used 6,565 products, four variants per family, and a 60-family page. Five runs compared the prior function with the revised function using identical helpers and asserted identical results. Warm median catalog grouping/hydration time fell from **64.89 ms to 19.40 ms**, approximately **70% less CPU time**. This is a local CPU benchmark, not a measured live end-to-end speedup. Raw evidence is in `output/catalog-page-hydration-benchmark.json`.

The final web export passes the 576 KiB gzip entry budget on all 11 checked routes. The latest route budget evidence is saved in `output/web-budget-2026-10-11.jsonl`; each reviewed route remains within budget. The common entry remains the largest contribution; routes already split their screen bundles and the quotation builder loads lazily.

Further work should prioritize measuring authenticated catalog/database/network timings after release, then testing a backend/database region nearer the main users. Railway supports regional placement ([official region documentation](https://docs.railway.com/deployments/regions)). Preserve route splitting and measure actual JS/network/render costs before another framework migration ([Expo async-route documentation](https://docs.expo.dev/router/web/async-routes/)). If Furniture documents routinely reach hundreds of rows, profile form rendering before introducing virtualization.
