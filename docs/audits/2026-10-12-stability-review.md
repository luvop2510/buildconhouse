## Confirmed root causes and fixes

1. **Missing catalog families and unstable list keys.** `mergeCatalogPage` and the catalog FlatList used bare supplier `family_key`, while backend grouping scopes it by floor, brand and category. Across pages, the client discarded separate valid cards. The shared `catalogItemKey` now preserves the full namespace, supplier listing occurrences, canonical product IDs and ungrouped product identity. Tests cover collisions, repeated pages, delimiter ambiguity and changes to the representative SKU. A read-only query of the configured live sanitary products found **14 reused supplier family keys affecting 32 products** across brand/category namespaces; no product data changed.
2. **Catalog thumbnails disagreed with detail.** Family listing and grouped search selected the first raw media row after already resolving the product's preview. An internal gallery image could replace the manufacturer's primary image, and a seat cover could replace an existing product photo. Both use the existing exact-product primary resolver now, and metadata describes the chosen URL. Two failing-before tests cover these cases. The fix preserves original images, supplier source cells, all catalog content and floor isolation.
3. **Safari login lost the first input during startup.** In current main CI, owner and worker sign-in stayed at `/login`. The recovered error context shows an empty username, filled password and the missing-credentials validation message. Trace inspection showed username entry into server-rendered HTML followed by replacement at hydration. Web login inputs are now read-only and the submit/mode controls unavailable until React mounts and handlers attach. A deterministic test holds the entry bundle, checks non-editability, releases it and verifies the exact submitted credentials and destination. Native interaction timing is preserved.
4. **Broken enforcement and incomplete CI visibility.** Main had no branch protection; failed checks had not prevented merging. Strict `backend`, `frontend`, `frontend-security` checks now apply, including administrators, with PRs required and force pushes/deletions blocked. Dependabot monitored legacy `/frontend` instead of the built root dependency graph; that is corrected. Independent browser suites now run after successful prerequisites even if another suite fails. Every failure still blocks CI and every suite's counts appear in the job summary.

These are specific repeat-regression mechanisms: duplicated identity rules across client/server, raw-media ordering bypassing the shared resolver, interactive SSR markup preceding handler readiness, legacy-source dependency monitoring, and unenforced failed checks. Prior fixes already protect asynchronous floor/account/route boundaries; they are preserved and rerun. No speculative architecture rewrite or fixed wait was introduced.
